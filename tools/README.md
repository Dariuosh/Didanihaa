# ابزارهای دیدنی‌ها

فرمان‌ها را با PowerShell 7 از ریشهٔ پروژه اجرا کنید:

```powershell
.\tools\Build-Publish.ps1  # ساخت آخرین تغییرات در publish؛ بدون اجرا
.\tools\Start-Didanihaa.ps1 # اجرای خروجی موجود؛ بدون ساخت
.\tools\Stop-Didanihaa.ps1  # توقف همان فرایندهای عادی
```

ساخت به SDK مطابق global.json و Node.js 22.18+ نیاز دارد. بستهٔ self-contained برای اجرا به SDK یا Node نیاز ندارد.

برای اجرای معمول، `Didanihaa.exe` را از ریشهٔ بسته باز کنید. کنسول وضعیت نمایش داده می‌شود و داشبورد روی `127.0.0.1` باز می‌شود. برای توقف، `Ctrl+C` بزنید، `Q` و سپس Enter را وارد کنید، یا پنجرهٔ کنسول را ببندید. `Stop-Didanihaa.ps1` برای اجراهایی که با PowerShell شروع کرده‌اید در دسترس است.

| فرمان | کاربرد |
| --- | --- |
| Build.ps1 | بازیابی قفل‌شده، ساخت و آزمون |
| Build-Publish.ps1 | ساخت بستهٔ ویندوز x64؛ بدون اجرا |
| Build-Release.ps1 | ساخت ZIP و checksum از commit ثبت‌شده، در ریشهٔ تمیز جداگانه |
| Start-Didanihaa.ps1 | اجرای بسته و بازکردن ادمین در مرورگر پیش‌فرض |
| Stop-Didanihaa.ps1 | توقف فرایندهای متعلق به همان راه‌انداز |
| Dev.ps1 / Stop-Dev.ps1 | شروع و پایان پیش‌نمایش توسعه |
| Run.ps1 | اجرای جداگانهٔ برنامه‌ها برای دیباگ |
| Enable-LanAccess.ps1 | عملیات مستقل UAC برای دسترسی محدود LAN |
| Test-Publication.ps1 | بررسی فایل‌ها و تاریخچه پیش از انتشار سورس |

ورودی اصلی شبکه پورت 13521 است: / برای TV و /admin/ برای مدیریت. راه‌انداز از مرورگر پیش‌فرض ویندوز استفاده می‌کند. Enable-LanAccess.ps1 فرمان جدا و دارای UAC برای قاعدهٔ محدود فایروال LAN است؛ build/start آن را اجرا نمی‌کنند و Media داخلی روی 13522 باز نمی‌شود.

## اولین استفاده

در ادمین منبع را اضافه کنید، پایان اسکن را ببینید و فایل‌ها یا فایل‌های مستقیم پوشهٔ دلخواه را صریحاً منتشر کنید. صفحهٔ TV فقط منتشرشده‌ها را نمایش می‌دهد. FFprobe برای مشخصات پیشرفته و FFmpeg برای تصویر بندانگشتی اختیاری‌اند. برای انتخاب نصب خودتان، تنظیمات ابزار را در داشبورد localhost روی دستگاه میزبان باز کنید و پوشهٔ bin یا یکی از دو فایل اجرایی را وارد کنید. مسیر خالی تشخیص خودکار از ffmpeg/bin و سپس tools را فعال می‌کند. پخش از فایل اصلی است.

## توسعه و به‌روزرسانی

برای توسعه، Build.ps1 سپس Dev.ps1 را اجرا کنید و با Stop-Dev.ps1 پایان دهید. Vite روی127.0.0.1:5211 است. تغییر C# نیازمند build و شروع دوبارهٔ بک‌اند است.

Dev.ps1 -WebOnly فقط پیش‌نمایش وب را به بک‌اند منتشرشدهٔ فعال متصل می‌کند؛ انتخاب و انتشار در آن، کاتالوگ واقعی همان بک‌اند را تغییر می‌دهد. Stop-Dev در این حالت فقط Vite ایجادشده را متوقف می‌کند.

پیش از Build-Publish، خروجی منتشرشدهٔ فعال را با Stop-Didanihaa متوقف کنید و پس از ساخت با Start-Didanihaa اجرا کنید. اگر Media سرویس ویندوز است، توقف/شروع آن از داشبورد انجام شود. تنظیمات و data موجود مقصد حفظ می‌شوند؛ data توسعه و publish/data مستقل‌اند.

وضعیت فرایندها و لاگ اجرای منتشرشده زیر `temp/runtime` همان بسته ذخیره می‌شوند؛ توسعه از `temp/dev` استفاده می‌کند. نسخهٔ جدید تا پیش از اولین ثبت وضعیت، فایل قدیمی `temp/dev/processes.json` را برای همان ریشه می‌خواند؛ ثبت‌های بعدی در مسیر تازه‌اند. فایل وضعیت و لاگ‌های قبلی بازنویسی یا حذف نمی‌شوند. وضعیت خراب یا متعلق به ریشه/حالت دیگر خطا می‌دهد تا مالکیت فرایندها بی‌صدا گم نشود.

راه‌انداز جدید هویت بک‌اند را با ریشه، نقش، فایل اجرایی، شناسهٔ اجرا و زمان شروع تطبیق می‌دهد؛ پاسخ health به‌تنهایی کافی نیست. هنگام ارتقا از بک‌اند قدیمی، ابتدا آن را با Stop متوقف کنید، سپس Build-Publish و Start را اجرا کنید؛ نسخهٔ قدیمی بدون هویت جدید به‌صورت خودکار بازاستفاده نمی‌شود. Start و Stop مشترکاً قفل عملیات دارند. توقف ناموفق رکورد مالکیت را حفظ می‌کند. اگر سرویس ثبت‌شده متعلق به پوشهٔ دیگری باشد، عملیات سرویس رد می‌شود؛ انتقال ثبت سرویس به مسیر تازه باید جداگانه انجام شود.

## سرویس و دسترسی شبکه

نصب سرویس اختیاری از داشبورد و با UAC انجام می‌شود. حساب LocalService باید به پوشهٔ رسانه دسترسی NTFS داشته باشد. نصب سرویس و build/start فایروال را تغییر نمی‌دهند.

عملیات install دسترسی خواندن/اجرا به ریشه و نوشتن محدود به `temp/runtime` را برای LocalService تنظیم می‌کند؛ این پوشه محل قفل و وضعیت اجرای سرویس است. برای ثبت قدیمی، همین عملیات پس از توقف سرویس، دسترسی تازه را هماهنگ می‌کند. سرویس متعلق به پوشهٔ دیگر تغییر نمی‌کند؛ در صورت آزادبودن پورت‌ها، اجرای عادی همین پوشه همچنان ممکن است.

برای مشاهدهٔ عملیات LAN بدون تغییر، `Enable-LanAccess.ps1 -WhatIf` را اجرا کنید. اجرای واقعی، قاعده را به برنامهٔ Control منتشرشده، TCP/publicPort، IP/interface منتخب و LocalSubnet محدود می‌کند. پس از انتقال بسته یا تغییر آدرس شبکه، قاعده نیازمند هماهنگی مجدد است. ادمین فعلاً login ندارد؛ دسترسی فقط روی LAN مورد اعتماد مناسب است.

در بستهٔ قابل انتقال نیز Start و Stop و internal در tools قرار می‌گیرند. FFprobe اختیاری و مجوزهای آن را می‌توان در همین پوشه گذاشت؛ exe/dll محلی در Git نادیده گرفته می‌شوند. مسیر ابزار از داشبورد تنظیم می‌شود.

## اشتراک سورس و بسته

Test-Publication.ps1 فایل‌های قابل ثبت فعلی و با -Revision HEAD -CheckHistory سابقهٔ همان ref را برای بعضی الگوهای خصوصی/خروجی کنترل می‌کند. این فرمان فایل یا تاریخچه را تغییر نمی‌دهد؛ اسکن اسرار و بررسی مجوز/هویت نویسنده جدا هستند.

بستهٔ قابل توزیع را از checkout تازه و تنظیمات نمونه بسازید. data شخصی، cache، لاگ، رسانه و ابزار خارجی را همراه نکنید. LICENSE، THIRD_PARTY_NOTICES و متن مجوز وابستگی‌ها باید در بسته بمانند. انتشار باینری و تغییرات سرویس/فایروال عملیات مستقل‌اند.

برای ساخت بستهٔ نسخه از commit فعلی:

```powershell
.\tools\Build-Release.ps1
```

این فرمان تغییرات سورسِ ثبت‌نشده را نمی‌پذیرد، commit عمومی انتخاب‌شده را در مسیر ثابت temp/releases/work/source دریافت می‌کند و خروجی ZIP و SHA256SUMS را در temp/releases/artifacts می‌گذارد. فضای ساخت موقت در اجرای بعدی بازسازی و با قفل از ساخت هم‌زمان محافظت می‌شود. publish و دادهٔ فعال پروژه دست‌نخورده می‌مانند. گزینه‌های -Revision و -OutputDirectory برای انتخاب commit و مقصد خروجی‌اند؛ مقصد نباید خروجی نسخهٔ قبلی داشته باشد. راهنمای داخل بسته از [Portable-README.md](Portable-README.md) تهیه می‌شود. این فرمان برنامه، tag یا Release گیت‌هاب را اجرا/ایجاد نمی‌کند.

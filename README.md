# دیدنی‌ها · Didanihaa

<img src="src/Didanihaa.WebUI/assets/brand/logomark.svg" alt="نشان دیدنی‌ها" width="72" height="72">

کتابخانهٔ شخصی صدا و ویدیو برای ویندوز و شبکهٔ محلی؛ فایل‌های دلخواهتان را از پوشه‌ها انتخاب کنید و با مرورگر تلویزیون، رایانه یا گوشی پخش کنید.

[English](README.en.md) · [راهنمای ابزارها](tools/README.md) · [مشارکت](CONTRIBUTING.md)

**معرفی پوشه ← اسکن و مشخصات ← بازبینی ← انتشار صریح ← پخش فایل اصلی**

اسکن هیچ فایلی را خودکار منتشر نمی‌کند. تغییر فایل منتشرشده، آن را به بازبینی برمی‌گرداند. هر پوشه پلی‌لیست فایل‌های مستقیم خودش است و زیرپوشه‌ها مستقل‌اند.

## قابلیت‌ها

- داشبورد فارسی و راست‌چین برای منابع، اسکن، انتشار، سرویس و تنظیمات.
- مرور پوشه‌ای، علاقه‌مندی مشترک، پربازدیدهای محلی و منوی قابل تنظیم.
- پلیر HTML5 با قبلی/بعدی، ترتیب عددی، تکرار پوشه، کنترل روی تصویر و تمام‌صفحه.
- فهرست قسمت‌های همان پوشه کنار پلیر و تصویر بندانگشتی واقعی ویدیو.
- نسخهٔ سادهٔ TV با مرور پوشه و پخش بومی، حتی با JavaScript خاموش.
- پخش فایل اصلی با HTTP Range و HEAD؛ بدون تبدیل کدک یا remux.
- تنظیمات و SQLite زیر ریشهٔ قابل انتقال؛ اجرای کنسولی یا Media به‌صورت Windows Service.

## دریافت نسخهٔ آماده

بستهٔ Windows x64 را از [Releases](https://github.com/Dariuosh/Didanihaa/releases) دریافت و استخراج کنید. با PowerShell 7 از پوشهٔ برنامه، `.\tools\Start-Didanihaa.ps1` را اجرا کنید؛ SDK و Node.js برای اجرای بسته لازم نیستند. [راهنمای بستهٔ قابل حمل](tools/Portable-README.md) نصب و به‌روزرسانی را توضیح می‌دهد.

## ساخت از سورس

پیش‌نیاز ساخت: Windows x64، PowerShell 7، [.NET SDK](https://dotnet.microsoft.com/download) مطابق [global.json](global.json)، و Node.js نسخهٔ 22.18 یا جدیدتر همراه npm. پروژه C# 15 / .NET 11، TypeScript، Lit و Vite دارد. اجرای بستهٔ پیش‌فرض self-contained به نصب SDK یا Node نیاز ندارد.

پس از دریافت سورس، PowerShell را در ریشهٔ پروژه باز کنید:

```powershell
# ساخت و آزمون توسعه
.\tools\Build.ps1

# ساخت بستهٔ مستقل در publish؛ بدون اجرای سایت
.\tools\Build-Publish.ps1

# اجرای بستهٔ ساخته‌شده و بازکردن ادمین در مرورگر پیش‌فرض
.\tools\Start-Didanihaa.ps1
```

در اولین ساخت، تنظیمات محلی از didanihaa.example.json ایجاد می‌شود. وابستگی‌ها به‌صورت محلی بازیابی می‌شوند؛ هیچ Windows Service یا قاعدهٔ فایروالی هنگام build/start نصب نمی‌شود.

| کاربرد | آدرس پیش‌فرض |
| --- | --- |
| تماشا در شبکه | `http://<LAN-IP>:13521/` |
| مدیریت | `http://<LAN-IP>:13521/admin/` |
| TV ساده | `http://<LAN-IP>:13521/tv/simple` |
| پیش‌نمایش Vite | `http://127.0.0.1:5211/admin/` و `/tv/` |
| Media داخلی | فقط loopback روی `13522` |

برای توقف بسته:

```powershell
.\tools\Stop-Didanihaa.ps1
```

ساخت و اجرا جدا هستند. پیش از بازسازی خروجی منتشرشده، فرایندهای آن را متوقف کنید. راهنمای [نصب اختیاری سرویس و دسترسی LAN](tools/README.md) مراحل تعاملی UAC و فایروال را توضیح می‌دهد.

## اولین کتابخانه

1. ادمین را باز کنید و یک پوشهٔ منبع اضافه کنید.
2. پایان اسکن و مشخصات شناسایی‌شده را بررسی کنید.
3. فایل‌ها یا فایل‌های مستقیم پوشهٔ دلخواه را صریحاً منتشر کنید.
4. «مشاهده در TV» یا صفحهٔ تماشا را باز کنید.

FFprobe برای مشخصات پیشرفته اختیاری است. مسیر آن از داشبورد قابل تنظیم است؛ برای نمونه `D:\Tools\ffmpeg\bin\ffprobe.exe`. اگر ffmpeg.exe کنار آن باشد، JPEG ثابت ویدیو ساخته می‌شود. این ابزارها همراه سورس توزیع نمی‌شوند و فایل اصلی برای پخش تغییر نمی‌کند. سازگاری کدک به دستگاه و مرورگر بستگی دارد.

## توسعه

```powershell
.\tools\Build.ps1
.\tools\Dev.ps1
# پس از پایان کار
.\tools\Stop-Dev.ps1
```

Vite فقط روی `127.0.0.1:5211` است و به gateway روی `13521` پراکسی می‌کند. تغییر C# نیازمند توقف، build و اجرای دوباره است. برای پیش‌نمایش سورس وب در کنار بک‌اند publish فعال، از `Dev.ps1 -WebOnly` استفاده کنید.

**کاتالوگ توسعه و بسته مستقل‌اند:** Dev عادی از data پروژه و نسخهٔ منتشرشده از publish/data استفاده می‌کند. انتخاب متفاوت در دو اجرا به معنی حذف انتشارهای قبلی نیست. Build-Publish تنظیمات و data موجود مقصد را حفظ می‌کند.

## مرز دسترسی و حریم خصوصی

دیدنی‌ها برای LAN مورد اعتماد است. ادمین روی همان پورت شبکه در دسترس است و فعلاً ورود/گذرواژه ندارد. Host/IP، Origin و توکن تغییرات بررسی می‌شوند؛ این کنترل‌ها جای احراز هویت کاربران شبکه را نمی‌گیرند. سرویس را مستقیماً روی اینترنت منتشر نکنید.

یک پروفایل مشترک «خانه» داریم. علاقه‌مندی و آمار پخش محلی در SQLite ذخیره می‌شوند؛ سرویس cloud، CDN یا telemetry بیرونی نداریم. فقط فایل‌های منتشرشده و موجود از مسیر پخش عمومی ارائه می‌شوند. جزئیات در [SECURITY.md](SECURITY.md) است.

تنظیمات واقعی، کاتالوگ‌ها، رسانه‌ها، cache، گزارش‌ها و خروجی publish در Git ثبت نمی‌شوند. برای اشتراک بسته، از checkout تازه و تنظیمات نمونه بسازید؛ پوشهٔ publish شخصی ممکن است اطلاعات خصوصی داشته باشد. دستورهای بررسی سورس در [راهنمای مشارکت](CONTRIBUTING.md) آمده‌اند.

## محدودیت‌ها

DLNA، Chromecast، transcoding/remux، زیرنویس قابل انتخاب، watcher و زمان‌بندی اسکن در این نسخه پیاده نشده‌اند. سازگاری کدک و کنترل پخش به دستگاه و مرورگر بستگی دارد. دسترسی Windows Service به رسانه‌ها تابع مجوزهای NTFS حساب سرویس است.
